## Défauts corrigés

- `rg --pre /bin/sh fichier` peut exécuter le contenu du fichier : le nom `rg` ne
  suffit pas à établir une simple lecture. Il est retiré de la liste partagée des
  utilitaires de niveau 0. Le chemin du code arbitraire (microVM et décision) s'applique.
- `sandbox.run` conservait sa poignée uniquement sur sa pile et échappait à
  `sandbox.list`, `sandbox.freeze_all`, `sandbox.thaw` et `sandbox.kill`. La poignée
  est maintenant partagée avec le registre pendant l'attente. Un lancement concurrent
  sur la même tâche est refusé ; la fin d'une ancienne commande ne retire pas sa remplaçante.
- Le test du bureau attendait l'identifiant Wayland `mousepad`. Le journal de CI
  prouve que la fenêtre est visible sous `org.xfce.mousepad` : le sélecteur est corrigé.
  Cela ne vaut pas encore une exécution réussie de toute la VM après correction.
- Le guide de sandboxd cesse de présenter Landlock comme appliqué : la fonction
  `apply_landlock` est un talon qui renvoie toujours `false`, même si son ABI est présente.

## Régressions exercées localement

Dans Ubuntu 24.04 / WSL2, avec le shell Nix du dépôt :

```sh
cargo test -p prophet-types ripgrep_peut -- --nocapture
cargo build -p sandboxd --bins
cargo test -p sandboxd --test run -- --include-ignored --nocapture
```

Les deux nouvelles régressions échouent avant correction. Après correction, celle de
la liste partagée passe et les deux tests du daemon `run` passent, sans test ignoré.
Le contrôle du gel lit l'état arrêté de `/proc/<pid>/status`, vérifie le conflit de
lancement, dégèle, tue, attend la réponse et vérifie la liste vide. Le test existant
de sortie, code de retour et délai reste vert.

## Limites qui interdisent de déclarer l'OS complet

- La CI stricte de ChatGPT sur cette base échoue sur Fontconfig.
- La publication sous l'identité du propriétaire sur NixOS reste non livrée ;
  une session de développement où les services partagent un UID ne la valide pas.
- Landlock n'est pas appliqué et le confinement complet du navigateur reste ouvert.
- L'ISO est un support d'installation en console, sans bureau Prophet exécutable en live.
- La variante CI `prophet-ci` n'inclut pas la suite complète d'applications ni le modèle
  par défaut de la configuration installée `prophet`.
- Une session Ubuntu/WSLg ne teste pas le chiffrement, les mises à jour, le retour
  arrière système, le démarrage du système installé ou la compatibilité matérielle.

Aucune exigence complète de `FRONTIER.md` n'est cochée par cet audit.
